# 051 Phase 3 database schema, migration and link store

- **Tier:** 3 (a migration on the hosted database, and the invariants every link depends on). **Suggested model:** Claude Opus.
- **Depends on:** 048. **Wave:** 2.

## Goal
Add the Phase 3 tables and enum values in one migration, and a small link store that is the only code allowed to write `registry_links` and the columns it fills.

## Why it matters
A wrong link misleads users. Keeping the link invariants (one link per company and per number, manual decisions final, duplicates turned into merge candidates) in one tested module means the Companies House step (056), the Form D step (057) and the review CLI (062) cannot drift apart.

## Steps
1. **Schema.** Add, exactly as spec section 5:
   - the appended enum values and new enums (Postgres enums built from the `src/core/enums.ts` arrays);
   - `registry_links` with its two partial unique indexes (`status = 'linked'`), `registry_searches`, `ch_companies`, `ch_filings`, `ch_address_counts`, `form_d_filings`, `edgar_index_days`, `event_confirmations` (FK cascade on `event_id`), `company_sectors`;
   - checks: amounts non-negative; `registry_links.method` not null when `status = 'linked'`; `company_sectors.sector` is not checked in SQL (the sector list is append-only in code, as for `themes.sector`);
   - relations for the new tables.
2. **Migration.** `pnpm db:generate` gives `drizzle/0003_*.sql`. Read it: enum values must be added with `ALTER TYPE ... ADD VALUE`, never by recreating the type. Note in the file header that `ADD VALUE` cannot run inside a transaction block on older Postgres; check it applies on PGlite and in the CI Postgres job.
3. **Roles.** Confirm none of the new tables holds article text, abstracts or personal data (spec section 5.6). Add a comment to `roles.sql` saying so, and that `ch_companies.office_postcode` is a company's public registered office, never displayed.
4. **`link-store.ts`**, used by every later writer of links:
   - `recordLink(db, { companyId, registry, registryId, registryName, method, reason, decidedBy, now })`:
     - if the company already has a manual `linked` or `rejected` row for this registry, an automatic call changes nothing;
     - if another company already holds this number as `linked`, insert a `candidate` row instead and add a merge candidate between the two companies with reason "same Companies House number" or "same SEC CIK" (`addMergeCandidate`); return `taken`;
     - otherwise upsert the `linked` row, fill `companies.uk_company_number` or `companies.sec_cik` when empty, and add the registry name as an alias with source `registry` (`ON CONFLICT DO NOTHING`);
   - `recordCandidate(...)`: inserts a `candidate` row unless any row exists for that company, registry and number;
   - `rejectLink(...)` and `unlink(...)`: manual only; `unlink` clears the company column only if it holds that number;
   - `demoteAutoLink(...)`: turns an automatic `linked` row back into `candidate` with a reason and clears the column (spec section 7.2, the only automatic unlink);
   - `recordSearch(db, { companyId, registry, outcome, inputFingerprint, now })` and `searchIsDue(db, companyId, registry, fingerprint, now)` (due when never searched, the fingerprint changed, or 90 days have passed).
   - Merged companies: every function follows `merged_into_id` to the survivor first.

## Tests and acceptance criteria
- `pnpm check` passes; the migration applies on PGlite (tests) and in the CI migrations job.
- `schema.test.ts`: every new table exists; the partial unique indexes reject a second `linked` row per company and registry, and per number; candidates for the same number on two companies are allowed.
- `link-store.test.ts` (PGlite):
  - a link fills the empty column and adds one `registry` alias; a second identical call changes nothing;
  - an existing `uk_company_number` held by another company makes a candidate and one merge candidate, never a second link;
  - a manual rejection blocks the same automatic link later; a manual link is never replaced by an automatic one;
  - `demoteAutoLink` clears the column; it refuses a manual link;
  - `searchIsDue` respects fingerprint and the 90-day rule;
  - calls on a merged company act on the survivor.
- No existing row is changed by the migration.
